What is vibe coding?

A way for non-technical people to create software by describing what they want in natural language, while AI generates the code behind the scenes.

"There's a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget the code even exists."

— Andrej Karpathy, Feb 2025

You describe what you want. AI writes the code. You get a working tool you can use in class on Monday.

CALIcon 26

Why vibe code?

  • You're the domain expert. You know your students, your doctrine, your classroom. That expertise is the hard part — the coding is now the easy part.
  • It builds real AI fluency. Being precise about what you want, iterating when the output isn't right, evaluating critically — these are the skills that matter for any professional AI use. And you get a useful tool at the end.
  • The cost of experimenting is near zero. Build a teaching tool in an afternoon. Try it once. Toss it or iterate. No vendor, no budget request, no instructional-design queue.
  • It changes what you're willing to try. When the cost of building drops, you pursue ideas you'd never have proposed before — and your students see what's possible too.

Things to keep in mind

  • Student data & FERPA — don't put student names, grades, or identifiable work into AI tools or vibe-coded apps
  • Accessibility — AI-generated code may not meet ADA standards; test with screen readers and iterate
  • Vet before classroom use — AI-written code can have bugs or wrong answers; click through it yourself first
  • Academic integrity — if students use the tool, be clear about what the tool does vs. what they do
  • Not legal advice — if the tool touches legal topics, label it as a teaching exercise

Before you share it, ask: "what data will this touch and who will use it?" A doctrinal decision tree is very different from a tool that collects student responses — and that answer shapes every later choice.

Steps to follow

CALIcon 26

Step 1: Identify a pedagogical pain point

  • A concept students consistently misunderstand
  • A doctrine that's hard to visualize on a slide
  • An exercise you'd love to assign but can't grade at scale
  • Information you find yourself re-explaining every semester
  • Something you've thought "there has to be a better way" about
CALIcon 26

Step 2: Choose a tool

Gemini Canvas

  • Free with any Google account
  • Describe what you want, get a live preview
  • Builds fast — first version in minutes
  • Great for decision trees, hypos, flashcards, timelines

Recommended for today. You'll have a working tool in the session.

Google AI Studio

  • Free with any Google account
  • Has a Build tab for creating apps
  • Builds are slower (10+ minutes)
  • Can incorporate AI — case readers, AI tutors, rubric feedback

More powerful, but slower. You may not finish in the session.

Other options: ChatGPT has Canvas and Claude has Artifacts — both can generate apps the same way.

CALIcon 26

Step 3: Plan with AI

Don't just say "build me an app." Have a conversation first.

  • Tell Gemini what you want students to learn and how they'll use the tool
  • Let it ask you questions — answer honestly (even "I'm not sure" is fine)
  • Go back and forth until you both understand what you're building
  • Then tell it to start building

Your prompt template ends with: "Before you start building, ask me a few questions about who this is for and what their experience should be like."

Working from a casebook PDF or article? Paste the text, not the file. LLMs handle raw text much better than document structure. If you need to convert, open a separate AI chat, drop in the PDF, and ask for plain text you can bring back over.

CALIcon 26

Step 4: Build it

  • Go to the Build tab — copy the prompt template or pick an idea card
  • Paste the prompt into Gemini and plan together
  • When you're ready to build, click "Canvas" under Tools
  • Test it — click through, try the inputs a confused student would try
  • Don't worry about getting it perfect on the first try

No Canvas button? That's OK — ask Gemini to write the code, then copy and paste it into the Preview tab on this site to see it run.

CALIcon 26

Step 5: Iterate

The first version is just the start. The real skill is the conversation you have with AI after that.

Pedagogical polish "Add a short explanation after each answer so students see why"
Edge cases "What if a student picks a weird combination of answers? Handle gracefully"
Hints "Add a 'hint' button that nudges without giving the answer away"
Accessibility "Make sure this works with a keyboard and a screen reader"
Mobile "Make this work well on a phone screen"
Export "Add a button so students can download their results as a PDF"
CALIcon 26

Step 6: Deploy

Before you share it, ask: what data does it touch? A decision tree with no student input is very different from a tool that collects responses.

Pick a path

  • Share the Canvas link — click Share in Canvas, send the URL (fastest)
  • Drop the HTML in your LMS — download the file, embed in Canvas/Blackboard/Moodle
  • Netlify Drop — drag a folder, get a live URL in 30 seconds
  • GitHub Pages — free, permanent URL you can keep updating

Before going public

  • If it collects student work — keep it inside your LMS, not on the open web
  • If it stores anything — loop in your IT/instructional-design folks for FERPA review
  • Don't paste real student work into Gemini while building

See the Deploy tab for step-by-step instructions.

What Canvas apps can & can't do

Your app CAN

  • Follow a decision tree (if/then logic)
  • Calculate scores, deadlines, or rubric points
  • Look things up in data you provide
  • Display feedback based on user choices
  • Enforce rules and flag mistakes

Your app CANNOT

  • Read and interpret a document
  • Summarize or paraphrase text
  • Answer open-ended student questions
  • Make judgment calls
  • Do anything requiring "understanding"

The index card test: If you could write every possible answer on index cards ahead of time, your app can handle it. If you'd need a smart person to figure out the answer — it can't. (For that, try Google AI Studio.)

Tools to keep building

You don't need to stop after today. Two paths, depending on how much setup you want.

One-stop platforms

Build and deploy in one place — all in the browser.

  • Replit — vibe-code and deploy in the browser; no local setup
  • Lovable — full web app from a prompt, one-click deploy
  • Bolt.new — similar browser-based full-stack builder

Developer stack

Maximum flexibility — requires installing a few tools.

  • Claude Code (Anthropic) — command-line AI agent; handles multi-file projects
  • GitHub — free code hosting with version history
  • Render — free-tier web hosting that redeploys on push from GitHub
